# PES Arena V1.6.79 — Realtime/Event-driven Upgrade

## Environment
Add **one browser-safe Supabase key** to Vercel/local `.env`:

- `SUPABASE_PUBLISHABLE_KEY=sb_publishable_...` (preferred for new Supabase projects), or
- `SUPABASE_ANON_KEY=...` (legacy projects).

Never put `SUPABASE_SERVICE_ROLE_KEY` or `SUPABASE_SECRET_KEY` in browser code.
The server continues to use the secret/service key.

## Architecture
- Invite / Quick Match: Supabase Broadcast event -> authenticated Flask API refresh.
- Room chat: Broadcast `CHAT_CHANGED` -> fetch authenticated chat snapshot.
- Room state / Ready: successful room POST -> `ROOM_CHANGED` or `PLAYER_READY` -> state sync.
- Online: Supabase Presence connection + sparse DB heartbeat fallback.
- Realtime failure: HTTP polling automatically remains as fallback.
- No sensitive row payload is sent through public Broadcast. Channel names are opaque HMAC topics generated by Flask.

## Fallback
Without a publishable/anon key the app keeps working using HTTP polling.
With Realtime connected, Invite/Chat/Room polling becomes sparse safety synchronization instead of the primary update path.
